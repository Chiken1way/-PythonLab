# Лабораторная работа №12. Итоговый проект — «План приготовления блюд»

- **Автор:** Гриша
- **Индивидуальный вариант:** №6 — План приготовления блюд (`amount` — количество порций, `completed` — блюдо приготовлено)
- **Версия Python:** 3.10.16 (совместимо с Python 3.8+, внешние библиотеки не требуются)

## Назначение программы

Консольное приложение для ведения локального плана приготовления блюд с хранением данных в JSON-файле `data.json`. Поддерживает просмотр, добавление, регистронезависимый поиск, изменение статуса приготовления, удаление с подтверждением, расчёт статистики по всем записям и по категориям, а также безопасное сохранение и проверку структуры входных данных.

## Структура проекта

```text
lab12/
    main.py          # Консольное меню, диалоги ввода/вывода, обработка ошибок
    logic.py         # Валидация, добавление, поиск, статус, удаление, статистика
    storage.py       # Чтение и запись JSON (UTF-8) без консольных диалогов
    test_logic.py    # Модульные тесты бизнес-логики
    test_storage.py  # Модульные тесты хранения JSON с TemporaryDirectory()
    data.json        # Вымышленный начальный набор данных (4 блюда)
    gui_example.py   # Пример минимального окна tkinter из методички
    README.md        # Документация проекта и результаты приёмки
```

Путь к `data.json` определяется относительно расположения `main.py` (`Path(__file__).resolve().parent / "data.json"`), поэтому проект корректно запускается после распаковки в любую папку.

## Формат данных (`data.json`)

Файл хранит JSON-массив словарей в кодировке UTF-8:

```json
[
  {"id": 1, "title": "Борщ", "category": "обед", "amount": 6, "completed": true},
  {"id": 2, "title": "Омлет с сыром", "category": "завтрак", "amount": 2, "completed": true},
  {"id": 3, "title": "Паста карбонара", "category": "обед", "amount": 4, "completed": false},
  {"id": 4, "title": "Сырники", "category": "завтрак", "amount": 3, "completed": false}
]
```

Ожидаемая статистика для начального набора: всего записей — `4`, приготовлено — `2`, не приготовлено — `2`, всего порций — `15`; по категориям (по алфавиту): `завтрак` — `5`, `обед` — `10`.

Правила валидации:
- `id` — положительное целое (`type is int`, `> 0`), уникальное в списке; новым записям присваивается `max(id) + 1` (или `1` для пустого списка), существующие ID после удаления не перенумеровываются.
- `title`, `category` — непустые строки после `strip()` (краевые пробелы убираются при добавлении).
- `amount` — целое неотрицательное число (`type is int`, `>= 0`; логические значения не принимаются).
- `completed` — строго `bool`.
- Дополнительные ключи в записях допускаются и сохраняются без обработки.

## Результаты сценариев приёмки

| Сценарий | Фактический результат | Статус |
|---|---|---|
| Файла `data.json` нет | Выведено сообщение, работа начата с пустым списком, меню доступно | Пройдено |
| JSON содержит `[]` | Список пуст (`Нет записей`), статистика: все количества и сумма равны `0` | Пройдено |
| Добавлены записи с количеством `4` и `2`, вторая завершена | Всего `2`, приготовлено `1`, не приготовлено `1`, сумма порций `6` | Пройдено |
| Название введено как `  Python  ` | Краевые пробелы удалены, сохранено `Python` | Пройдено |
| Поиск `PY` при названии `Python` | Запись найдена без учёта регистра | Пройдено |
| Пустое название, `amount=-1`, `amount=abc` | Выведены сообщения об ошибке и повторный ввод, лишняя запись не создана | Пройдено |
| Изменение статуса неизвестного ID | Выведено сообщение о том, что ID не найден, данные не изменены | Пройдено |
| Удаление отменено (ответ не `да`) | Выведено «Удаление отменено», запись сохранена | Пройдено |
| Удалена запись с ID `1` из списка с ID `1` и `2` | Осталась запись с ID `2`; следующая добавленная запись получила ID `3` | Пройдено |
| Сохранение и перезапуск | Все поля, категории, порции и статусы полностью восстановлены | Пройдено |
| Повреждённый JSON или повторный ID | Запуск прекращён с пояснением причины; исходный файл не изменён | Пройдено |
| Ошибка сохранения | Сообщение об успехе не выведено; программа осталась в меню | Пройдено |
