# Лабораторная работа №11. JSON и получение данных по HTTP

## Цель работы

Научиться читать и записывать данные в формате JSON, проверять корректность их структуры, отделять сетевые HTTP-запросы от локальной обработки данных и покрывать логику тестами без зависимости от интернета.

## Структура проекта

- `json_example.py` — базовый пример сериализации и десериализации JSON с сохранением кириллицы (`ensure_ascii=False`, `indent=2`).
- `todos.json` — исходный учебный набор задач.
- `analysis.py` — функции валидации (`validate_todos`), подсчёта завершённых задач (`completion_counts`), поиска лидеров (`top_users`), отбора задач лидеров (`leader_completed_tasks`) и работы с JSON-файлами (`load_todos`, `save_json`).
- `main.py` — запуск локального анализа `todos.json`, вывод сводки и сохранение завершённых задач лидеров в `leaders.json` с обработкой ошибок.
- `variant6.py` — отдельный модуль и скрипт для **индивидуального варианта №6** (задачи указанного пользователя с чётным `id`), сохраняет результат в `selected.json`.
- `leaders.json` — сохранённые завершённые задачи пользователей-лидеров (`id`: `[1, 3, 4, 5]`).
- `selected.json` — сохранённый результат выборки по варианту №6 для `user_id=5` (`id`: `[2]`).
- `fetch_profile.py` — скрипт HTTP-упражнения с консольным меню (выбор между запросом к GitHub API и чтением локального примера) и общей функцией вывода профиля.
- `profile_sample.json` — учебный локальный файл профиля для работы без доступа к сети (`{"login": "demo", "id": 1, "name": null}`).
- `test_analysis.py` — модульные тесты (`unittest`), проверяющие все требования без сетевых вызовов.

## Индивидуальный вариант №6

Файл: `variant6.py`.

- **Условие:** отобрать задачи указанного пользователя (`user_id`) с **чётным `id`**.
- **Дополнительный параметр:** не требуется (`parameter=None`).
- **Проверка на учебном наборе:** при `user_id=5` отбирается задача с `id=2` (`[2]`).
- **Поведение:** ввод `user_id` повторяется до получения положительного целого числа; порядок записей сохраняется; для неизвестного пользователя возвращается `[]`; исходные записи не изменяются.

## Запуск

```bash
# Базовый пример JSON
python json_example.py

# Обязательная часть: анализ todos.json -> leaders.json
python main.py

# Индивидуальный вариант №6 -> selected.json
python variant6.py

# HTTP-упражнение (выбор сети или локального примера)
python fetch_profile.py

# Запуск тестов
python -m unittest test_analysis.py -v
```

## Пояснения к HTTP-упражнению (`fetch_profile.py`)

- **Назначение адреса (`https://api.github.com/users/<login>`):** конечная точка REST API GitHub для получения публичного профиля пользователя по его логину (а не данных конкретного репозитория). Логин безопасно кодируется функцией `urllib.parse.quote(..., safe="")`.
- **Метод `GET`:** используется по умолчанию в `urllib.request.Request` без тела запроса; предназначен для чтения ресурса на сервере без его изменения.
- **Таймаут (`timeout=10`):** ограничивает время ожидания ответа сервера 10 секундами, чтобы программа не зависала бесконечно при недоступности сети или медленном соединении.
- **Обработчики ошибок:**
  - `HTTPError` — перехватывает HTTP-коды ошибок от сервера (например, `404` — пользователь не найден, `403`/`429` — превышен лимит запросов или запрещён доступ) и выводит код статуса.
  - `URLError`, `TimeoutError`, `socket.timeout` — обрабатывают сетевые сбои (нет интернета, ошибка DNS, разрыв или истечение времени ожидания).
  - `json.JSONDecodeError`, `ValueError`, `UnicodeError` — перехватывают некорректный ввод (пустой логин), ошибки декодирования UTF-8, битый JSON и неожиданную структуру ответа (например, отсутствие строкового поля `login`).
  - `OSError` — обрабатывает ошибки доступа к файловой системе при чтении или сохранении файла.
- **Локальный режим:** в работе использованы учебные локальные данные из `profile_sample.json` (`{"login": "demo", "id": 1, "name": null}`), так как упражнение выполнялось в режиме без доступа к интернету. Значение `null` для поля `name` не подменяется выдуманными данными. В `fetch_profile.py` добавлено консольное меню выбора источника (сеть или локальный пример) с общей функцией вывода `display_profile`.
